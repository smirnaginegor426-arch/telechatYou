# TeleChatYou — что изменено

## 1. Восстановление пароля
- **Вход (`/login`)**: поля username и пароля, кнопка «Забыл пароль?», вход через Kimi сохранён.
- **Восстановление (`/recover`)**:
  1. Ввод username → «Получить код».
  2. Код формата `AAA1-BBB1-CCCC1` (буквы A–Z, в каждой группе одна цифра 1–9).
  3. «Скопировать». Кнопка «Продолжить» появляется только после копирования.
  4. Ввод кода, новый пароль и повтор. Код одноразовый, действует 15 минут,
     блокируется после 5 неверных попыток, и предыдущие коды аннулируются при новом запросе.
- **Настройки → Аккаунт → Пароль**: установка пароля, смена (нужен текущий пароль).
- Пароли хешируются scrypt (встроенный модуль Node, без новых зависимостей).
  В базе хранится только хеш кода восстановления (SHA-256), сам код не хранится.

Новые таблицы: `credentials`, `recovery_codes`. Колонка `settings.animations`.
Применить: `npm run db:push` или выполнить `db/manual/password-recovery.sql`.

## 2. Исправления ошибок
- «Анимации в чатах» управляли тем же полем, что и «Автозагрузка медиа». Теперь у них отдельные
  настройки, а анимация аврора-фона отключается через атрибут `data-anim` на `<html>`.
- Нельзя редактировать удалённое сообщение (сервер теперь возвращает ошибку).
- Ошибки загрузки файла (модерация, квота, размер) показываются понятным текстом, а не общей ошибкой.
- Экран входа приведён к стилю TeleChatYou и получил кнопку «Назад».
- Текст на стартовом экране больше не утверждает, что паролей нет.

## 3. Сборка APK
Папка `mobile/` — оболочка Capacitor, которая открывает развёрнутый https-сайт TeleChatYou.
Подробности и команды: `mobile/README.md`.

## ⚠ Известные ограничения (обязательно прочитать)
- **Восстановление пароля по одному username небезопасно.** Код выдаётся тому, кто вводит
  username, поэтому любой, кто знает username, может сбросить пароль чужого аккаунта.
  До публичного запуска нужен второй канал: доставка кода владельцу (например, через Kimi),
  подтверждение входом через Kimi или e-mail. Сейчас поведение соответствует заданию.
- Цифры в коде: задано «1–10», но одна цифра не может быть 10, поэтому используется 1–9.
  Поменять можно в `api/lib/recovery-code.ts` (`DIGITS`).
- Ограничение частоты запросов хранится в памяти процесса и сбрасывается при перезапуске.
- Ответ «Пользователь не найден» при восстановлении раскрывает, существует ли username.
- Не проверено на реальном запуске: в среде сборки не было доступа к npm и Android SDK,
  поэтому `npm install`, `vite build`, работа с MySQL и сборка APK не выполнялись.
  Хелперы паролей и кодов проверены отдельно на Node (см. раздел тестов в отчёте).
