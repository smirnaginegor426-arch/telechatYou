# TeleChatYou — самостоятельный запуск

Проект представляет собой React/Vite-приложение с Hono + tRPC API и MySQL-совместимой базой данных. Файлы можно хранить локально для разработки или в постоянном Cloudinary media storage для размещения на облачном хостинге. Вход через Kimi удалён; аккаунты создаются самим приложением.

## Требования

- Node.js 20 или новее
- MySQL 8+ или TiDB Cloud (MySQL-compatible)
- Для постоянного хранения на облачном хостинге используйте Cloudinary или S3-совместимое хранилище. У Render Free нет постоянного диска, поэтому локальную папку нельзя использовать для пользовательских файлов в production.

## Настройка

1. Скопируйте `.env.example` в `.env`.
2. Укажите `DATABASE_URL` с данными из TiDB Cloud. Используйте базу `telechatyou`. Для удалённой базы приложение включает TLS и проверку сертификата. Если пароль содержит `@`, `:`, `/`, `%` или другие специальные символы, URL-кодируйте пароль.
3. Установите случайный `SESSION_SECRET` не короче 32 символов; не публикуйте `.env` и не добавляйте его в GitHub.
4. Установите пакеты: `npm install`.
5. Для пустой базы примените схему: `npm run db:push`.
6. Запуск для разработки: `npm run dev`.
7. Производственная сборка: `npm run check` и `npm run build`, затем `npm start`.

`npm run db:push` синхронизирует схему Drizzle с базой. Файл `db/migrations/0001_local_auth.sql` предназначен только для уже существующей базы прежней версии с Kimi-авторизацией; не запускайте его после `db:push` на той же базе, поскольку он повторно добавит колонки.

## Файлы

После регистрации аккаунта пользователь проходит экран настройки профиля, где задаёт публичное имя и username. Имя для входа (логин) и публичный username хранятся раздельно.

Загруженные изображения/аудио/документы сохраняются:
- локально в `UPLOAD_DIR` (по умолчанию `./data/uploads`) для разработки;
- как закрытые authenticated raw assets в Cloudinary, если заданы `CLOUDINARY_CLOUD_NAME`, `CLOUDINARY_API_KEY` и `CLOUDINARY_API_SECRET`;
- в S3-совместимое хранилище, если заданы соответствующие `S3_*` переменные. Cloudinary имеет приоритет, если настроены оба варианта.

**Render Free использует эфемерную файловую систему:** файлы на диске пропадают при перезапуске, повторном развёртывании или остановке неактивного сервиса. Не используйте локальный режим для постоянных пользовательских загрузок на Render Free.

### Настройка постоянного хранилища Cloudinary (без банковской карты)

1. Зарегистрируйтесь на [Cloudinary Free](https://cloudinary.com/users/register_free). Официально бесплатный тариф не требует карты; в нём действует месячный лимит кредитов.
2. Откройте Cloudinary Console → **Settings → API Keys**. Скопируйте **Cloud name**, **API Key** и **API Secret**.
3. В Render откройте сервис `telechatYou-1` → **Environment** и добавьте `CLOUDINARY_CLOUD_NAME`, `CLOUDINARY_API_KEY` и `CLOUDINARY_API_SECRET`.
4. Сохраните изменения и дождитесь успешного деплоя. Не загружайте важные новые файлы, пока Render не станет **Live**.
5. Проверьте отправку фото в чате. Перезапустите сервис и проверьте фото повторно.

Файлы загружаются в Cloudinary как **authenticated raw assets**, а сервер генерирует короткоживущие подписанные ссылки только для чтения и отдаёт контент через существующий маршрут `/api/files/*` после проверки сессии. Не добавляйте ключи в GitHub, код или сообщения. Следите за бесплатным лимитом Cloudinary (хранилище и передача данных расходуют кредиты).

Если в аккаунте Cloudinary вы не видите API Keys, сначала завершите подтверждение регистрации/почты.

Объекты, уже потерянные из-за эфемерного диска, не восстановятся сами. Чтобы перенести доступные старые загрузки, их надо скопировать в bucket до потери файлов либо загрузить пользователями заново.

## Ограничения текущей версии

- Серверные сессии хранятся в таблице `sessions`, в БД записывается только HMAC-хеш случайного токена.
- Ссылки `/api/files/...` доступны только пользователю с действительной сессией. Текущая проверка защищает от анонимного доступа; разграничение доступа на уровне конкретных чатов следует добавить до размещения конфиденциальных файлов в публичном сервисе.
- Пароль для аккаунта не восстанавливается автоматически; пока нет email/телефона для сброса. Пользователь должен сохранить его в надёжном менеджере паролей.
- Для production обязательно используйте HTTPS, надёжный `SESSION_SECRET`, TLS-подключение к базе и постоянное файловое хранилище. Cloudinary Free ограничен месячными кредитами; превышение лимита не должно обходиться автоматической привязкой карты — аккаунт не переводите на платный тариф без явного решения.


## Каналы и опросы

- Канал создаётся через **Новый чат → Каналы**. Укажите название, аватар, описание и выберите публичный или приватный режим.
- У публичного канала должен быть уникальный username от 3 до 32 символов (латинские буквы, цифры и подчёркивание). Публичные каналы видны в каталоге и доступны по username.
- Приватные каналы не показываются в каталоге. Владелец может приглашать участников через экран информации о канале.
- Только владелец и администраторы могут публиковать сообщения, файлы и опросы в канале. Подписчики могут читать публикации и голосовать.
- Опрос поддерживает 2–10 вариантов, один или несколько ответов, подсчёт результатов и закрытие опроса.
- В production при старте приложения новые таблицы каналов и опросов создаются автоматически через `CREATE TABLE IF NOT EXISTS`. Для локальных установок есть SQL-файл `db/migrations/0002_channels_polls.sql`.
