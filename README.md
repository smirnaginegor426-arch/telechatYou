# TeleChatYou — самостоятельный запуск

Проект представляет собой React/Vite-приложение с Hono + tRPC API и MySQL-совместимой базой данных. Файлы можно хранить локально для разработки или в постоянном S3-совместимом объектном хранилище (например, Cloudflare R2) для размещения на облачном хостинге. Вход через Kimi удалён; аккаунты создаются самим приложением.

## Требования

- Node.js 20 или новее
- MySQL 8+ или TiDB Cloud (MySQL-compatible)
- Для постоянного хранения на облачном хостинге нужен S3-совместимый bucket или persistent disk. У Render Free нет постоянного диска, поэтому для бесплатного web-сервиса используйте S3/R2.

## Настройка

1. Скопируйте `.env.example` в `.env`.
2. Укажите `DATABASE_URL` с данными из TiDB Cloud. Используйте базу `telechatyou`. Для удалённой базы приложение включает TLS и проверку сертификата. Если пароль содержит `@`, `:`, `/`, `%` или другие специальные символы, URL-кодируйте пароль.
3. Установите случайный `SESSION_SECRET` не короче 32 символов; не публикуйте `.env` и не добавляйте его в GitHub.
4. Установите пакеты: `npm install`.
5. Для пустой базы примените схему: `npm run db:push`.
6. Запуск для разработки: `npm run dev`.
7. Производственная сборка: `npm run check` и `npm run build`, затем `npm start`.

`npm run db:push` синхронизирует схему Drizzle с базой. Файл `db/migrations/0001_local_auth.sql` предназначен только для уже существующей базы прежней версии с Kimi-авторизацией; не запускайте его после `db:push` на той же базе, поскольку он повторно добавит колонки.

## Файлы

После регистрации аккаунта пользователь проходит экран настройки профиля, где задаёт публичное имя и username. Имя для входа (логин) и публичный username хранятся раздельно.

Загруженные изображения/аудио/документы сохраняются:
- локально в `UPLOAD_DIR` (по умолчанию `./data/uploads`) для разработки;
- в частный S3-совместимый bucket, если заданы `S3_ENDPOINT`, `S3_BUCKET`, `S3_ACCESS_KEY_ID` и `S3_SECRET_ACCESS_KEY`.

**Render Free использует эфемерную файловую систему:** файлы на диске пропадают при перезапуске, повторном развёртывании или остановке неактивного сервиса. Не используйте локальный режим для постоянных пользовательских загрузок на Render Free.

### Настройка постоянного хранилища Cloudflare R2

1. В Cloudflare откройте **Storage & databases → R2** и создайте bucket, например `telechatyou-files`.
2. Создайте R2 API token с правами **Object Read & Write** только для этого bucket.
3. В Cloudflare возьмите S3 endpoint вида `https://<ACCOUNT_ID>.r2.cloudflarestorage.com`, Access Key ID и Secret Access Key.
4. В Render откройте сервис `telechatYou-1` → **Environment** и добавьте переменные `S3_ENDPOINT`, `S3_BUCKET`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY`, `S3_REGION=auto`.
5. Сохраните изменения и дождитесь успешного деплоя. После этого новые загрузки будут отправляться в R2 и переживут перезапуски Render.

Не добавляйте ключи в GitHub, код или сообщения. Bucket должен оставаться приватным: TeleChatYou отдаёт файлы через серверный endpoint с проверкой сессии.

Объекты, уже потерянные из-за эфемерного диска, не восстановятся сами. Чтобы перенести доступные старые загрузки, их надо скопировать в bucket до потери файлов либо загрузить пользователями заново.

## Ограничения текущей версии

- Серверные сессии хранятся в таблице `sessions`, в БД записывается только HMAC-хеш случайного токена.
- Ссылки `/api/files/...` доступны только пользователю с действительной сессией. Текущая проверка защищает от анонимного доступа; разграничение доступа на уровне конкретных чатов следует добавить до размещения конфиденциальных файлов в публичном сервисе.
- Пароль для аккаунта не восстанавливается автоматически; пока нет email/телефона для сброса. Пользователь должен сохранить его в надёжном менеджере паролей.
- Для production обязательно используйте HTTPS, надёжный `SESSION_SECRET`, TLS-подключение к базе и постоянное файловое хранилище.
