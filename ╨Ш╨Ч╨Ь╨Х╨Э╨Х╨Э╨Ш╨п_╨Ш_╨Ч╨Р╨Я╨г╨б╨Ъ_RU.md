# TeleChatYou — что изменено и как запускать

## Что изменено

- Убран обязательный OAuth-вход через Kimi. Теперь есть регистрация и вход по имени пользователя и паролю.
- Пароль хранится не в открытом виде: используется scrypt с уникальной солью.
- Добавлены серверные сессии с случайным токеном в HttpOnly-cookie; в базе хранится HMAC-хеш токена.
- Добавлена таблица `sessions` и поля `users.username`, `users.passwordHash`; старый `unionId` стал nullable.
- Файлы сохраняются на диск сервера в каталоге `UPLOAD_DIR`; ссылки выдаются через `/api/files/...` и требуют активную сессию.
- Настроена TLS-поддержка удалённой MySQL/TiDB-базы.
- Сохранены имеющиеся интерфейс чатов, профили и экраны приложения.

## Первый запуск с вашей пустой базой TiDB

1. Распакуйте архив и откройте папку `app`.
2. Скопируйте `.env.example` в файл `.env`.
3. В `.env` укажите соединение `DATABASE_URL`:
   `mysql://USERNAME:URL_ENCODED_PASSWORD@HOST:4000/telechatyou`
   Вставьте свои данные TiDB, а вместо базы `sys` используйте `telechatyou`. Пароль со спецсимволами должен быть URL-кодирован. Не отправляйте `.env` никому и не добавляйте его в GitHub.
4. Укажите случайное значение `SESSION_SECRET` длиной не менее 32 символов.
5. Установите Node.js 20 или новее, затем выполните в терминале из папки `app`:
   - `npm install`
   - `npm run db:push` — создаёт таблицы в пустой базе.
   - `npm run dev` — запускает проект для разработки.
6. Откройте `http://localhost:3000`, нажмите «Начать», затем зарегистрируйте аккаунт.

Если база уже содержит старые таблицы TeleChatYou от прежнего Kimi-проекта, **не запускайте `db:push` до резервного копирования**. Для обновления старой схемы есть `db/migrations/0001_local_auth.sql`; применяйте её только один раз и только к старой схеме. К пустой базе этот SQL применять не нужно.

## Важно для постоянного бесплатного хостинга

- Хостингу нужен Node.js runtime, а не только статическое размещение фронтенда.
- Подключите постоянный диск/volume и задайте `UPLOAD_DIR` на его путь. На временном диске фото и файлы могут пропасть при перезапуске или новом деплое.
- Для production обязательно используйте HTTPS и собственный случайный `SESSION_SECRET`.
- Файловые URL сейчас требуют входа, но проверяют сессию, а не членство в конкретном чате. Перед использованием для приватных переписок нужно добавить проверку доступа к файлу по участникам чата.

## Статус проверки

Синтаксис 127 TypeScript/TSX-файлов проверен парсером TypeScript — синтаксических ошибок не найдено. Полную проверку типов, npm-сборку и подключение к реальной базе выполнить не удалось: установка npm-зависимостей в среде сборки зависла и была остановлена. Поэтому архив ещё нужно проверить `npm run check` и `npm run build` в среде с установленными зависимостями до публикации.


## Исправление TypeScript-проверки

После первой локальной проверки были внесены дополнительные исправления:
- middleware авторизации теперь явно передаёт проверенного пользователя в защищённые tRPC-процедуры;
- тип базы данных выводится из фабрики создания подключения, чтобы избежать конфликта типов Drizzle/mysql2;
- `StorageError` больше не использует параметр-свойство конструктора, несовместимое с `erasableSyntaxOnly`;
- URL зависимостей в `package-lock.json` переведены с недоступного зеркала на `https://registry.npmjs.org/`.

После распаковки этой версии запустите `npm ci`, затем `npm run check`. Эти исправления ещё необходимо подтвердить локальной проверкой; до её завершения проект нельзя считать полностью собранным или готовым к публикации.
